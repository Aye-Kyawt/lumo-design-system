### When to use it
> Use a toast to confirm that something happened after the user acted — saved, sent, deleted, failed — without interrupting what they are doing.

<small>From the Lumo.Web.Component.V1.0.Complete library — the `toast` description, read 2026-10-19.</small>

### Where it goes
- overlaid, away from the content the user is working in

### When not to use it
- Don’t use it for anything the user must act on; that is a Modal or an Alert.
  - **Use instead:** `Modal or an Alert` — not implemented in this library yet.

### Props
| Prop | Type | Default | Notes |
|---|---|---|---|
| `status` | `'positive'|'negative'|'warning'|'info'` | `'positive'` | Figma `Status`. The only variant property in the set. |
| `title` | `string` | `'Report saved'` | Figma `Title` (151:134). The bold first line. |
| `description` | `boolean` | `true` | Figma `Description`, the boolean. Shows or hides the second line. |
| `descriptionText` | `string` | `'Q3 2026 AI value report is ready to share.'` | Figma `Description`, the text. Renamed per the Empty State precedent — the set spells the boolean and the text with one name. See docs/naming-conflicts.md. |
| `close` | `boolean` | `true` | Figma `Close`. Shows or hides the dismiss control. |
| `iconName` | `string` | `'check'` | Figma `↳Icon`, as a Material Symbols glyph name rather than a node — the Button precedent in docs/naming-conflicts.md. Defaults to `check`, which is what the node draws in all four statuses (gap 2). |
| `onClose` | `() =&gt; void` | — | Not a Figma property. The close control is drawn but has nothing to do in a static frame; this is what it does. Without it the button still renders and is still focusable, because the node draws it — it simply has no handler, exactly as the design specifies it. |
| `closeLabel` | `string` | `'Close'` | Not a Figma property. The accessible name for the close control, whose glyph is `aria-hidden` decoration. |
| `className` | `string` | `''` |  |
