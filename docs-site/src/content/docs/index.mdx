## What this site is

The reference layer of the Lumo Design System. Storybook shows you what a
component *does*; this site says what it is *for* — when to reach for it, when
not to, what it pairs with, and which tokens a correct use of it must supply.

The two are deliberately separate. Storybook is built from the component source
on every push. This site is written by reading the Figma documentation and the
repo and reporting where the two disagree.

<Aside type="note" title="Six components are documented; three are still shells">
Button, Badge, Card, Switch, Progress and Empty State carry a written intent
record — every field of the contract answered, from two sources read and
compared. Accordion, Field and Toast have not shipped yet and are still
shells.

Each record says where the Figma documentation and the repo **disagree**,
giving both sides without picking one, and says plainly where **neither**
source states something rather than inventing a sentence nobody decided. Every
disagreement is collected on one page: [Figma vs the repo](/disagreements/).

This does not release anything. A component reaches `Released` only when
`Astro Link`, `Release Review` and `Release Verdict` = `Cleared` are all set.
`Astro Link` now points at these pages for all six — written after each was
opened and watched render. The verdicts still read `Blocked`, so none of the
six is released, and the version in the hero is not a release either.
</Aside>

## How a component gets here

A component moves through the registry one written cell at a time. No status is
set by hand; each is derived from evidence somebody wrote after seeing it.

| Status | What it means | Who acts next |
|---|---|---|
| `To-do` | Figma node exists and the design is signed off | Engineer builds it |
| `Ready for Testing` | A staging build exists and renders | QA tests every variant, size and state |
| `To be fixed` / `Fixing` | A test case failed | Engineer repairs it |
| `Fixed` | The repair is claimed | QA re-tests it |
| `To be deployed` | Every test case passed | DevOps promotes it |
| `Completed` | It is live in production | Doc-generator documents it; Release reviews it |
| `Released` | Documented, reviewed and cleared | Nobody — it is done |

A human approves a release. No agent approves its own work.
