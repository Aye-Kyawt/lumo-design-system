### When to use it
> Use field to wrap any input control with a label, an optional required mark and helper or error text — used by Input, Select, Textarea and Checkbox groups alike.

<small>From the Lumo.Web.Component.V1.0.Complete library — the `field` description, read 2026-10-19.</small>

### Where it goes
- in a form, wrapping one input control

### When not to use it
- Don’t write the field’s own error styling into the control; field carries it.
  - **No alternative named.** The source states the prohibition without saying what to reach for instead.

### Props
| Prop | Type | Default | Notes |
|---|---|---|---|
| `state` | `'default'|'error'|'disabled'|'Type'` | `'default'` | Figma `State`. `Type` is the set's own spelling for the filled state — see docs/naming-conflicts.md for why it was kept and what was suggested back. |
| `label` | `string` | `''` | Figma `Label` (141:3120). The text of the label row. |
| `required` | `boolean` | `false` | Figma `Required` (141:3121), the mark hidden in all four variants. Shows the red asterisk and appends `requiredText` for screen readers. |
| `requiredText` | `string` | `'required'` | Not a Figma property. The asterisk is decoration, so the word a screen reader announces has to come from somewhere; this is it. |
| `helper` | `boolean` | `true` | Whether the helper row shows at all. The node draws it in every variant. |
| `helperText` | `string` | `''` | Figma `Helper` (141:3125 / 141:3135). In `error` this is the error message and the row grows an icon. |
| `iconName` | `string` | `'close'` | Material Symbols glyph for the error icon. Defaults to `close`, which is what node 90:8 draws. |
| `children` | `React.ReactNode` | — | The `↳Control` slot (141:3122 and friends). Put the real Input, Select, Textarea or Checkbox group here. Named `children` per the Card precedent in docs/naming-conflicts.md, since the field has exactly one slot. |
| `id` | `string` | — | Seeds the ids of the label row (`$&#123;id&#125;-label`) and the helper row (`$&#123;id&#125;-helper`), so a control in the slot can reference either. Generated when absent — and a generated id is useless to you, so pass one whenever you need to wire `aria-labelledby` or `aria-describedby`. |
| `controlId` | `string` | — | The `id` of the labelable control inside the slot. Pass it and the label gets `for`; omit it and the label gets no `for` at all. There is no guessed default: the field cannot see what you put in the slot, and a `for` pointing at nothing is worse than none. Only pass this for an element `for` can legally name — input, select, textarea, button, meter, output, progress. For anything else (a checkbox or radio group, a custom combobox), leave it off and point that thing at `$&#123;id&#125;-label` with `aria-labelledby`. |
| `className` | `string` | `''` |  |
